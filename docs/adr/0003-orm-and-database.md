# ADR-0003 — Drizzle, Postgres, and connection strategy

**Status:** Accepted · **Date:** 2026-08-03 · **Closes:** decision D7

## Context

Spec §15.3 calls for managed Postgres reachable from both Vercel functions and
the worker, with connection pooling. TASK-01's sharpest caveat is the serverless
connection storm: "without pooling you will exhaust Postgres connections under
load."

## Decision

**Drizzle over Prisma.** Prisma's query engine is a native binary that has to be
present in the serverless bundle and in the worker container. Drizzle is
TypeScript that compiles away, which suits an architecture already shipping
TypeScript source across packages. Drizzle also emits plain SQL migrations that
a reviewer can read — which matters because migrations here are a gated,
human-approved step.

**`postgres-js` with `prepare: false`.** Transaction-mode poolers (PgBouncer,
the Neon pooler) do not keep prepared statements across a transaction boundary;
leaving prepares on produces intermittent, hard-to-reproduce failures.

**Pool size 1 per serverless instance in production.** The pooler multiplexes.
A large per-instance pool just relocates the exhaustion problem.

**Two connection strings.** `DATABASE_URL` is pooled and used by the app;
`DATABASE_URL_UNPOOLED` is direct and used only by migrations — DDL over a
transaction pooler fails in confusing ways.

## Email is `text` with a unique index, not `citext`

The spec suggests `citext`. A unique index over a value normalised to lowercase
at the validation layer achieves the same guarantee without requiring an
extension to be installable on every managed Postgres.

## Consequences

- Migrations are generated by `drizzle-kit` and applied by a custom runner that
  **refuses destructive statements** without `--allow-destructive`. See
  `docs/runbooks/migrations.md`.
- Row types are inferred from the schema, so `packages/types` holds DTOs and
  domain shapes rather than duplicated table types.
- `audit_log` should be granted INSERT and SELECT only at the database-role
  level so its append-only property is enforced by Postgres, not convention.
  See `docs/runbooks/database-roles.md`.
